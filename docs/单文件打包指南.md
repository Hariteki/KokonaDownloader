# 海兔下载器 — 单文件 exe 打包指南

> 适用版本：v1.0.6+ · .NET 8 · WinUI 3 · Windows App SDK 1.8
> 目标产物：单个 `KokonaDownloader.exe`（约 303 MB），复制到任意可写目录即可独立运行，无需安装、无需附带文件。

---

## 一、问题背景

### 1.1 为什么单文件 exe 会"跑不起来"

.NET 8 的 `PublishSingleFile` 只把 **托管程序集和原生库** 打进 exe，以下"松散文件"默认**不会**被打包：

| 文件 | 作用 |
|---|---|
| `resources.pri` | WinUI 3 资源映射表（XBF 索引） |
| `*.xbf` | 编译后的 XAML 二进制 |
| `aria2c.exe` | 下载引擎 |
| `icons\tray.ico` / `icons\tray.png` | 托盘图标 |

更隐蔽的坑：单文件 bundle 运行时，`AppContext.BaseDirectory` 指向 **临时解压目录**（`%TEMP%\...`），而 **不是** exe 所在目录。WinUI 3 的 XAML 运行时通过 `ms-appx:` URI 从 **exe 所在目录** 加载 XBF/PRI，两者不一致 → `XamlParseException`。

### 1.2 修复思路

```
┌─────────────────────────────────────────────────────────┐
│  构建时                                                  │
│  1. 编译 XAML → XBF（obj 目录）                          │
│  2. makepri 生成 resources.pri（bin 目录）               │
│  3. 把 XBF + PRI + aria2c.exe + 图标 嵌入 exe            │
│     （EmbeddedResource, LogicalName = "standalone/..."） │
├─────────────────────────────────────────────────────────┤
│  运行时（[ModuleInitializer]，XAML 初始化之前）           │
│  1. baseDir = Path.GetDirectoryName(Environment.ProcessPath)│
│  2. 若 baseDir\resources.pri 已存在 → 跳过               │
│  3. 否则：从嵌入资源解压 12 个文件到 baseDir              │
│  4. 若 baseDir 只读 → 回退 %LOCALAPPDATA%\...\Standalone │
│     复制 exe 过去并重新拉起                               │
└─────────────────────────────────────────────────────────┘
```

## 二、csproj 关键配置

### 2.1 基础属性

```xml
<PropertyGroup>
  <TargetFramework>net8.0-windows10.0.19041.0</TargetFramework>
  <RuntimeIdentifier>win-x64</RuntimeIdentifier>
  <UseWinUI>true</UseWinUI>
  <WindowsPackageType>None</WindowsPackageType>
  <WindowsAppSDKSelfContained>true</WindowsAppSDKSelfContained>
  <Version>1.0.6</Version>
  <AssemblyVersion>1.0.6.0</AssemblyVersion>
  <FileVersion>1.0.6.0</FileVersion>
  <InformationalVersion>1.0.6</InformationalVersion>
  <!-- PRI 文件名（默认就是 resources.pri，显式声明更清晰） -->
  <ProjectPriFileName>resources.pri</ProjectPriFileName>
</PropertyGroup>
```

### 2.2 嵌入独立运行载荷

核心思路：把"构建产物"（XBF、PRI、aria2c、图标）标记为 `EmbeddedResource`，并给每个文件一个 `standalone/` 前缀的逻辑名称。

```xml
<!-- ═══════════════════════════════════════════════════════
     嵌入独立运行载荷（XBF + PRI + aria2c + 图标）
     ═══════════════════════════════════════════════════════ -->
<ItemGroup>
  <!-- 8 个应用 XBF（obj 目录，排除 embed 子目录的副本） -->
  <EmbeddedResource Include="$(IntermediateOutputPath)**\*.xbf"
                    Exclude="$(IntermediateOutputPath)embed\**"
                    WithCulture="false" Type="Non-Resx" />
  <!-- PRI 资源映射表 -->
  <EmbeddedResource Include="$(TargetDir)$(ProjectPriFileName)"
                    WithCulture="false" Type="Non-Resx" />
  <!-- aria2c 下载引擎 -->
  <EmbeddedResource Include="..\..\vendor\aria2\aria2c.exe"
                    WithCulture="false" Type="Non-Resx" />
  <!-- 托盘图标 -->
  <EmbeddedResource Include="..\..\icons\titlebar-tray\tray.ico"
                    WithCulture="false" Type="Non-Resx" />
  <EmbeddedResource Include="..\..\icons\titlebar-tray\icon-32.png"
                    WithCulture="false" Type="Non-Resx" />
</ItemGroup>
```

### 2.3 自定义 MSBuild 任务：设置 LogicalName

MSBuild 的 `EmbeddedResource` 项默认用相对路径作为逻辑名称，我们需要改成 `standalone/...` 前缀。用 Roslyn 内联任务实现：

```xml
<Target Name="EmbedStandalonePayload" BeforeTargets="_GenerateCompileInputs">
  <!-- 依赖链：确保 PRI 已生成、XBF 已编译 -->
  <PropertyGroup>
    <_EmbedDependsOn>_GetSdkToolPaths;GetMrtPackagingOutputs;_GetDefaultResourceLanguage;_GenerateProjectPriFile</_EmbedDependsOn>
  </PropertyGroup>

  <SetStandaloneLogicalNames
    Items="@(EmbeddedResource)"
    Prefix="$(IntermediateOutputPath)"
    ProjectDir="$(MSBuildProjectDirectory)">
    <Output TaskParameter="ResultItems" ItemName="_StandaloneEmbeddedResources" />
  </SetStandaloneLogicalNames>

  <!-- 用带 LogicalName 的项替换原始 EmbeddedResource -->
  <ItemGroup>
    <EmbeddedResource Remove="@(EmbeddedResource)" />
    <EmbeddedResource Include="@(_StandaloneEmbeddedResources)" />
  </ItemGroup>
</Target>
```

> **关键坑**：内联任务必须用 `[Output] ResultItems` 往返，不能直接修改传入的 `Items` 集合（MSBuild 项是只读副本，直接改会丢失）。

### 2.4 XBF 拷贝到 bin（供 makepri 使用）

```xml
<Target Name="CopyXbfToBinForPri" BeforeTargets="_GenerateProjectPriConfigurationFiles">
  <ItemGroup>
    <_XbfFiles Include="$(IntermediateOutputPath)**\*.xbf"
               Exclude="$(IntermediateOutputPath)embed\**" />
  </ItemGroup>
  <Copy SourceFiles="@(_XbfFiles)"
        DestinationFolder="$(TargetDir)%(RecursiveDir)"
        SkipUnchangedFiles="true" />
</Target>
```

### 2.5 发布后拷贝 XAML 资源到输出目录

```xml
<Target Name="CopyXamlResourcesToPublishDir" AfterTargets="Publish">
  <ItemGroup>
    <_PublishXbf Include="$(IntermediateOutputPath)**\*.xbf"
                 Exclude="$(IntermediateOutputPath)embed\**" />
  </ItemGroup>
  <Copy SourceFiles="@(_PublishXbf)"
        DestinationFolder="$(PublishDir)%(RecursiveDir)"
        SkipUnchangedFiles="true" />
  <Copy SourceFiles="$(TargetDir)$(ProjectPriFileName)"
        DestinationFiles="$(PublishDir)$(ProjectPriFileName)"
        SkipUnchangedFiles="true" />
</Target>
```

## 三、StandaloneBootstrap.cs（运行时解压）

```csharp
using System;
using System.Collections.Generic;
using System.IO;
using System.Linq;
using System.Runtime.CompilerServices;

namespace KokonaDownloader.App;

internal static class StandaloneBootstrap
{
    private const string ResourcePrefix = "standalone/";

    [ModuleInitializer]
    internal static void InitializeStandaloneBootstrap()
    {
        try
        {
            EnsureRuntimeFiles();
        }
        catch
        {
            // 尽力而为：解压失败不阻止启动（开发构建可能没有嵌入资源）
        }
    }

    internal static void EnsureRuntimeFiles()
    {
        // ⚠️ 关键：单文件 bundle 中 AppContext.BaseDirectory 指向临时解压目录，
        //    不是 exe 所在目录。XAML 运行时从 exe 目录加载 XBF/PRI，
        //    所以必须用 Environment.ProcessPath 推导。
        var exePath = Environment.ProcessPath;
        if (string.IsNullOrEmpty(exePath))
            return;
        var baseDir = Path.GetDirectoryName(exePath) + Path.DirectorySeparatorChar;

        // 完整目录布局：resources.pri 已在 exe 旁，无需处理
        if (File.Exists(Path.Combine(baseDir, "resources.pri")))
            return;

        var asm = typeof(StandaloneBootstrap).Assembly;
        var names = asm.GetManifestResourceNames()
            .Where(n => n.StartsWith(ResourcePrefix, StringComparison.Ordinal))
            .ToList();
        if (names.Count == 0)
            return; // 未嵌入载荷的开发构建（如 IDE 直接运行），无需处理

        // 1) 首选：解压到 exe 旁
        try
        {
            ExtractAll(asm, names, baseDir);
            return;
        }
        catch
        {
            // 目录只读 → 走回退路径
        }

        // 2) 回退：解压到 %LOCALAPPDATA%\KokonaDownloader\Standalone，从那里重新拉起
        var fallback = Path.Combine(
            Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData),
            "KokonaDownloader", "Standalone");
        Directory.CreateDirectory(fallback);
        ExtractAll(asm, names, fallback);

        var targetExe = Path.Combine(fallback, Path.GetFileName(exePath));
        try
        {
            File.Copy(exePath, targetExe, overwrite: true);
        }
        catch
        {
            // 目标 exe 正被另一实例占用 → 直接复用已解压好的那份
        }

        var psi = new System.Diagnostics.ProcessStartInfo
        {
            FileName = targetExe,
            UseShellExecute = false,
        };
        foreach (var arg in Environment.GetCommandLineArgs().Skip(1))
            psi.ArgumentList.Add(arg);

        System.Diagnostics.Process.Start(psi);
        Environment.Exit(0);
    }

    private static void ExtractAll(System.Reflection.Assembly asm,
                                   List<string> names, string root)
    {
        foreach (var name in names)
        {
            var rel = name[ResourcePrefix.Length..].Replace('\\', '/');
            var dest = Path.GetFullPath(Path.Combine(root, rel));

            // 路径穿越防护
            if (!dest.StartsWith(Path.GetFullPath(root), StringComparison.OrdinalIgnoreCase))
                throw new SecurityException($"Path traversal blocked: {rel}");

            var destDir = Path.GetDirectoryName(dest);
            if (!string.IsNullOrEmpty(destDir))
                Directory.CreateDirectory(destDir);

            using var stream = asm.GetManifestResourceStream(name);
            if (stream == null)
                throw new FileNotFoundException($"Embedded resource not found: {name}");

            using var fs = File.Create(dest);
            stream.CopyTo(fs);
        }
    }
}
```

### 关键设计点

| 设计点 | 说明 |
|---|---|
| `[ModuleInitializer]` | 在 `Main()` 之前、XAML 初始化之前运行，确保文件就位 |
| `Environment.ProcessPath` | 单文件 bundle 中 `AppContext.BaseDirectory` 不可靠，必须用 `ProcessPath` |
| 跳过逻辑 | `resources.pri` 已存在 → 直接返回（开发构建 / 已解压场景） |
| 路径穿越防护 | `dest.StartsWith(root)` 检查，防止恶意资源名 |
| 只读回退 | 解压失败 → `%LOCALAPPDATA%\KokonaDownloader\Standalone` + 重新拉起 |
| 静默容错 | `try/catch` 包裹，解压失败不阻止启动（开发构建可能没有嵌入资源） |

## 四、构建命令

### 4.1 构建（开发调试）

```powershell
dotnet build src\KokonaDownloader.App\KokonaDownloader.App.csproj -c Release -r win-x64
```

### 4.2 发布（单文件 exe）

```powershell
dotnet publish src\KokonaDownloader.App\KokonaDownloader.App.csproj `
  -c Release -r win-x64 `
  --self-contained true `
  -p:PublishSingleFile=true `
  -p:IncludeNativeLibrariesForSelfExtract=true `
  -p:WindowsAppSDKSingleFileVerifyConfiguration=false `
  -o dist\KokonaSingleFile
```

> **参数说明**：
> - `--self-contained true`：自包含 .NET 运行时（用户无需安装 .NET）
> - `-p:PublishSingleFile=true`：单文件发布
> - `-p:IncludeNativeLibrariesForSelfExtract=true`：原生库也打进 exe
> - `-p:WindowsAppSDKSingleFileVerifyConfiguration=false`：跳过 WASDK 单文件配置校验（WASDK 1.8 的已知限制）

### 4.3 产物

```
dist\KokonaSingleFile\
├── KokonaDownloader.exe    ← 唯一需要的文件（~303 MB）
├── resources.pri           ← 构建时拷贝（运行时 StandaloneBootstrap 会跳过）
├── *.xbf                   ← 构建时拷贝（同上）
├── aria2c.exe              ← 构建时拷贝（同上）
└── icons\
    ├── tray.ico
    └── tray.png
```

> 发布目录中的松散文件是"开发便利"——如果用户直接从这个目录运行，`resources.pri` 已存在，`StandaloneBootstrap` 会跳过解压。
> **分发给用户时只需要 `KokonaDownloader.exe` 一个文件。**

## 六、已知坑与解决方案

| 坑 | 现象 | 解决方案 |
|---|---|---|
| `AppContext.BaseDirectory` 指向临时目录 | XBF/PRI 解压到错误位置，XAML 崩溃 | 用 `Environment.ProcessPath` 推导 exe 目录 |
| MSBuild 内联任务修改项集合无效 | LogicalName 丢失 | 用 `[Output] ResultItems` 往返 |
| `EmbeddedResource` 默认逻辑名称是相对路径 | 资源名不匹配 | 自定义任务设置 `standalone/` 前缀 |
| makepri 找不到 XBF | PRI 生成失败 | `CopyXbfToBinForPri` 在 `_GenerateProjectPriConfigurationFiles` 之前拷贝 |
| WASDK 单文件校验失败 | 构建报错 | `-p:WindowsAppSDKSingleFileVerifyConfiguration=false` |
| 只读目录解压失败 | 启动崩溃 | 回退到 `%LOCALAPPDATA%` + 重新拉起 |
| `Path.GetFullPath` 转换 `/` → `\` | 路径不匹配 | `ExtractAll` 中 `Replace('\\', '/')` 归一化 |
| 路径穿越 | 恶意资源名写入任意位置 | `dest.StartsWith(root)` 检查 |
